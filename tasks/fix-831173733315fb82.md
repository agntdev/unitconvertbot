# fix-831173733315fb82 — parseNumber breaks on comma-as-thousands-separator like "1,234.56"

**Weight:** 0.0000 (share of project budget)
**Reward:** 0 UCB

`src/utils/parseNumber.ts` (line 2) replaces ALL commas with dots globally: `input.trim().replace(/,/g, ".")`. For `"1,234.56"` (comma as thousands separator + dot as decimal) this produces `"1.234.56"` → `Number("1.234.56")` = **NaN**. The spec expects `Number("1234.56")` = 1234.56. The `tests/specs/E2T1.json` spec (line 17-21) expects `/parsenumber 1,234.56` to reply `"1234.56"`, but the implementation throws and replies `"Please provide a valid number."` instead. The function only handles comma as a **decimal** separator (e.g. `"3,14159"` → 3.14159), not as a thousands separator alongside a decimal dot.
