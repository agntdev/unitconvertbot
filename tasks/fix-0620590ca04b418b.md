# fix-0620590ca04b418b — E3T1 error middleware does not cover handlers loaded before it

**Weight:** 0.0000 (share of project budget)
**Reward:** 0 UCB

The E3T1 handler implements error handling as a grammY middleware (`composer.use(async (ctx, next) => { try { await next(); } catch ... })`). However, `buildBot()` in `src/bot.ts:44` loads handlers in sorted alphabetical order via `bot.use()`, which appends middleware to the chain. E3T1 is loaded at position 6 in the chain, **after** E1T1, E1T2, E1T3, E1T4, and E2T1. These 5 handlers run *before* E3T1's error boundary, so their errors are **not** caught and do **not** receive the user-facing "An error occurred; please try again" reply. The task spec states "Wrap the logic of **each** command handler in a try/catch block" — this requirement is not met for handlers loaded before E3T1.

In production, errors from those 5 handlers fall through to `bot.catch()` (set in `src/toolkit/bot.ts:47`), which logs but does not reply to the user. In tests, they surface as step failures in the harness.
